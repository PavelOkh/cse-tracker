# CSE и DPD — массовая проверка доставки

Подготовлено по приложенной инструкции ws-integration-guide-en.docx, раздел 9 «Status tracking», и исходному CSE_app.py из https://github.com/PavelOkh/cse-tracker (получен 16.10.2026).

## Обновление 16 октября — публичный режим без ключа

В приложении DPD теперь два режима. По умолчанию выбран «Публичный сайт — без ключа». В этом режиме поля API-реквизитов не используются, год приёма не передаётся. Список примеров находится в sample_waybills.txt.

Публичный режим выполняет GET https://dpd.ru/search/НОМЕР и разбирает HTML: сверяет номер заказа, находит значение по подписи «Дата доставки» и статус. Дата попадает в фактическую доставку только если статус начинается с «Доставлен». Исходное значение отдельно сохраняется в «Дата доставки на сайте». Публичная страница показывает результат по заказу, полнота доставки каждого места этим режимом не проверяется.

На пользовательском скриншоте для 31020008913 видны статус «Доставлен (Тольятти)», дата 02.10.2026 и успешный GET страницы (HTTP 200). Это контрольный пример со скриншота, не результат живого опроса разработанным кодом. Скриншот Elements показывает итоговый DOM: наличие данных именно в исходном HTML ещё требует проверки. Если HTML пустой и данные подгружаются JavaScript, текущий парсер сообщит ошибку и потребует доработки по реальному ответу.

Из среды подготовки сервер публичной страницы вернул HTTP 403 с сообщением о блокировке ботов. Работа из Streamlit Cloud или с вашего ПК пока не подтверждена. При HTTP 403/429 программа останавливает дальнейшие сетевые запросы; блокировку не обходит и не маскирует как отсутствие накладной. Не добавляйте cookies из личного браузера.

Протестирован разбор 5 искусственных HTML-примеров, построенных по скриншоту, и 5 ответов SOAP. Исходный HTML DPD, браузерный интерфейс и живые статусы списка ещё не проверены. Для точной проверки парсера сохраните страницу DPD как HTML через браузер и передайте файл (без cookies и заголовков авторизации).

Порядок обновления: замените файлы приложения из архива, обновите requirements.txt, оставьте app.py главным файлом. Выберите DPD → «Публичный сайт — без ключа», сначала проверьте 31020008913. Ожидаемый по скриншоту результат — 02.10.2026. При ошибке разметки не считайте отправление недоставленным.

## Запуск на компьютере

1. Установите Python 3.11 или 3.12.
2. Распакуйте архив в отдельную папку.
3. В терминале этой папки выполните:

```bash
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Слева выберите CSE или DPD. Для DPD введите номер клиента и API-ключ. Вставьте список номеров или загрузите CSV/XLSX с заголовками и выберите нужный столбец. Номера должны храниться как текст, особенно с ведущими нулями. Нажмите «Проверить», затем скачайте XLSX.

## Добавление в существующий Streamlit Community Cloud

1. Скопируйте в свой репозиторий app.py, dpd_tracker.py, requirements.txt и сохраните исходный CSE_app.py рядом. Можно использовать все файлы этого архива.
2. В настройках приложения измените главный файл с CSE_app.py на app.py. Если настройка недоступна, создайте второе приложение из того же репозитория с главным файлом app.py.
3. В Settings → Secrets задайте:

```toml
DPD_CLIENT_NUMBER = "ВАШ_НОМЕР_КЛИЕНТА"
DPD_CLIENT_KEY = "ВАШ_API_КЛЮЧ"
```

4. Перезапустите приложение, выберите DPD и проверьте одну известную доставленную накладную и одну находящуюся в пути.
5. Сравните статус и дату с личным кабинетом DPD. Для многоместного заказа проверьте каждое место. После этого проверяйте массовый список.

Не записывайте рабочий ключ в GitHub. Если приложение доступно посторонним, они смогут выполнять запросы с сохранёнными реквизитами: ограничьте доступ средствами хостинга или вводите ключ вручную в личном сеансе. Ключи не входят в выгрузку и сообщения ошибок.

## Условия DPD и смысл результата

- Требуются clientNumber и clientKey, выданные DPD, и включённая опция Parcel Tracing. По инструкции история начинает сохраняться после подключения услуги; старые отправления могут быть недоступны.
- Используется getStatesByDPDOrder(request={auth, dpdOrderNr, pickupYear?}). Нужен номер ЗАКАЗА DPD, не произвольный номер штрихкода места. Для clientOrderNr и clientParcelNr существуют другие методы; в эту версию они не включены. Термин waybill сам по себе не определяет тип идентификатора.
- Год приёма необязателен, но уточняет номер, уникальный только в пределах года. Для списка с разными годами запускайте отдельные проверки по годам.
- Никаких confirm/getStatesByClient нет: история читается по конкретному заказу и не подтверждает получение общей очереди событий.
- Последний статус выбирается по transitionTime, а не положению в массиве. Дата доставки берётся только из Delivered. Плановая дата не считается фактической.
- Одна строка на место, дату приёма и направление (обычное/возврат). Многоместный заказ может быть доставлен частично. Возврат со статусом Delivered означает доставку возврата, а не первоначальному получателю. Связанный заказ выводится, но автоматически не опрашивается.
- no-data-found также возможен до обработки на терминале приёма; это не доказательство неправильного номера. no-setting означает необходимость подключения услуги.
- Неизвестные коды сохраняются. Время выводится в формате ответа DPD без выдуманного часового пояса.
- Запросы последовательные, с паузой 0,3 с и ограниченными повторами временных HTTP-ошибок. Дубликаты номеров удаляются с сохранением порядка.
- Используется HTTPS. Если DPD не предоставляет рабочий TLS endpoint для договора/окружения, нужно уточнить адрес у поддержки DPD, а не передавать ключ по HTTP.

## Проверки и ограничения

```bash
python -m unittest discover -s . -p 'test_dpd.py' -v
```

Проверены синтаксис и 5 сценариев обработки искусственных ответов: история не по порядку и частичная доставка, отдельный возврат, пустая история, отсутствие времени, неизвестный статус.

Живой запрос с реквизитами клиента и интерфейс Streamlit ещё не проверены. Попытка получить WSDL из среды подготовки вернула HTTP 502. SOAP-схема загружается zeep из WSDL при запуске; доступность endpoint и совместимость с реальным ответом требуют проверки на одной накладной. Создание отправлений и другие операции записи не используются.

Исходный CSE_app.py сохранён без изменений; его существующая обработка, повторы и XLSX работают в прежнем виде и не входили в проверку DPD. Код репозитория не опубликован и облачное приложение не изменено.
